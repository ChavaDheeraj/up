QUALITATIVE RESEARCH ANALYSIS SYSTEM — END-TO-END SYSTEM EXPLANATION & DOCUMENTATION
Study Topic: Perceived Safety of Solo Women Travellers
Methodology: Braun & Clarke (2006) 6-Stage Qualitative Thematic Analysis
================================================================================

--------------------------------------------------------------------------------
1. SYSTEM OVERVIEW & CORE PURPOSE
--------------------------------------------------------------------------------
This application is a specialized Machine Learning (ML) and Artificial Intelligence (AI) 
qualitative research workspace designed explicitly for analyzing research documents 
related to "Perceived Safety of Solo Women Travellers".

The primary purpose of this system is to assist researchers by automating the 6 stages 
of Braun & Clarke (2006) Thematic Analysis while keeping the researcher in total control:
    "The AI proposes. The evidence supports. The researcher validates."

The methodology separates three distinct research datasets:
  A. Blog Analysis (~40 public solo-travel blog posts written by women)
  B. Interview Analysis (~50 semi-structured interview transcripts with international women students)
  C. Survey Component (~400 quantitative responses mapped separately for Phase 3 SEM analysis)

Core Theoretical Framework:
  Physical & Social Constraints -> Perceived Safety -> Destination Image -> Travel Intention -> Experiential Well-Being & Self-Leadership


--------------------------------------------------------------------------------
2. END-TO-END PAGE & SECTION-BY-SECTION EXPLANATION
--------------------------------------------------------------------------------

[SECTION 1: OVERVIEW DASHBOARD]
- Purpose: Serves as the executive command center for the qualitative research project.
- Key Functions & Display:
  1. Dataset Metrics: Displays real-time counts for Total Documents, Blogs (40), 
     Interviews (50), Total Words Analyzed, Generated Codes, and Final Themes.
  2. Braun & Clarke Stepper: Visual 8-step pipeline indicator showing the current stage 
     of analysis (Ingestion -> Familiarisation -> Initial Coding -> Codebook -> Themes -> 
     Review & Compare -> Framework & Validate -> Report).
  3. Construct Frequency Distribution: Graphical breakdown showing the relative 
     prevalence of the 7 core theoretical constructs across all coded text passages.

[SECTION 2: UPLOAD DATA (INGESTION PIPELINE)]
- Purpose: Handles document ingestion, text extraction, segmentation, and automated ML coding.
- Key Functions & Display:
  1. Multi-File Drag-and-Drop Zone: Ingests raw research files in PDF, DOCX, TXT, HTML, and CSV formats.
  2. Dataset Classifier: Allows the user to select whether the uploaded document is a 
     Public Blog Post (40 cohort) or an Interview Transcript (50 cohort).
  3. Instant Execution & Direct Output Tables: Upon processing, the system renders 3 
     comprehensive output tables directly beneath the ingestion section:
     - Table 1 (Document Overview): Document ID, Filename, Title, Word Count, Paragraph Count, 
       Thematic Safety Density %, Dominant Construct, and Dominant Emotional Tone.
     - Table 2 (Construct Frequency Breakdown): Construct Name, Frequency, Percentage, 
       and Theoretical Definition.
     - Table 3 (Key Evidence Quotes): Primary Construct, Sub-dimension, Verbatim Quote, 
       Confidence Score, and Emotional Tone.
  4. Direct Excel Report Download: Provides a direct link to download the complete Excel analysis workbook.

[SECTION 3: DOCUMENTS REPOSITORY]
- Purpose: Manages and catalogs all 90 study documents (blogs and interviews).
- Key Functions & Display:
  1. Filterable Table: Filter documents by Dataset Type (Blog / Interview), Processing Status, 
     or search by Title/ID.
  2. Document Familiarisation Summary Modal: Clicking "Familiarisation" opens a detail drawer 
     outlining:
     - Main Experience
     - Destination Context
     - Traveller Context
     - Key Safety Concerns
     - Emotional Responses
     - Positive & Negative Lived Experiences

[SECTION 4: INITIAL QUALITATIVE CODING]
- Purpose: Passage-level qualitative coding view providing complete evidence traceability.
- Key Functions & Display:
  1. Verbatim Quotations: Shows every coded text unit extracted from uploaded documents.
  2. Evidence Traceability: Displays exact Document ID (e.g. BLOG_01, INT_04), Dataset Type, 
     and Paragraph Number for every single quote. Never fabricates text.
  3. Indicators & Metadata: Shows assigned Construct, Sub-dimension, Confidence Score (0.00-1.00), 
     Emotional Tone (Vulnerability & Fear, Calculated Caution, Empowerment & Confidence), and Matched Keywords.

[SECTION 5: DYNAMIC CODEBOOK]
- Purpose: Central repository for all qualitative codes generated by the model.
- Key Functions & Display:
  1. Code Table: Displays Code Name, Definition, Verbatim Evidence Sample, Construct, 
     Occurrence Frequency, Document Reach, Confidence Score, and Status.
  2. Researcher Controls: Inline buttons allow the researcher to Approve or Reject codes. 
     Approved codes feed into theme generation.

[SECTION 6: CANDIDATE THEMES & SUB-THEMES]
- Purpose: Clusters related codes into higher-order theoretical themes.
- Key Functions & Display:
  1. Theme Cards: Displays Theme Name, Theoretical Definition, Subthemes, Related Codes, 
     Blog Frequency vs. Interview Frequency, and Verbatim Evidence Count.
  2. Researcher Actions: Allows researchers to Approve Theme, Reject Theme, Rename Theme, 
     Merge Themes into another, or Split Themes.

[SECTION 7: BLOG VS INTERVIEW COMPARISON]
- Purpose: Compares public voluntary blog narratives against direct semi-structured interview transcripts.
- Key Functions & Display:
  1. Comparative Matrix: Side-by-side comparison table showing how each construct manifests in Blogs vs. Interviews.
  2. Insight Tags: Explicitly tags themes as Convergence (present in both), Divergence (stronger in one cohort), 
     Blog-Specific, or Interview-Specific.
  3. Analytic Synthesis: Summarizes structural differences (e.g., blogs emphasize advice and empowerment; 
     interviews reveal acute night-time fear, paternalistic family judgment, and lodging security flaws).

[SECTION 8: CONCEPTUAL FRAMEWORK MAPPING]
- Purpose: Maps findings directly to the theoretical model:
  Physical & Social Constraints -> Perceived Safety -> Destination Image -> Travel Intention -> Well-Being & Self-Leadership
- Key Functions & Display:
  1. Evidence Mapping: Connects Theme -> Construct -> Verbatim Quote -> Document ID & Paragraph #.
  2. Evidence Categorization: Explicitly distinguishes between:
     - Direct Evidence (explicitly stated by participant)
     - Reasonable Interpretation (analytical inference)
     - Theoretical Interpretation (broader theoretical link)

[SECTION 9: CONTRADICTIONS & NEGATIVE EVIDENCE]
- Purpose: Prevents confirmation bias by identifying conflicting participant accounts.
- Key Functions & Display:
  1. Comparative Case Cards: Juxtaposes positive safety experiences (e.g., feeling completely safe in night markets) 
     against negative safety experiences (e.g., feeling terrified in dimly lit streets).
  2. Contextual Nuance: Explains conditions (e.g., street lighting, crowd density, police presence) under which safety perceptions change.

[SECTION 10: RESEARCHER VALIDATION AUDIT]
- Purpose: Human-in-the-loop validation dashboard tracking researcher overrides and calculating model performance metrics.
- Key Functions & Display:
  1. Validation Metrics: Displays Agreement Rate %, Macro Precision, Macro Recall, F1 Score, 
     Code Agreement %, and Theme Agreement %.
  2. Audit Log Table: Full chronological log of every researcher approval, rejection, modification, and timestamp.

[SECTION 11: BLIND MODEL TESTING]
- Purpose: Evaluation suite allowing researchers to run blind tests to evaluate model reliability.
- Key Functions & Display:
  1. Blind Testing Engine: Hides ground-truth labels and runs the qualitative coding model independently.
  2. Benchmark Metrics: Calculates exact Agreement Rate, Macro Precision, Macro Recall, and F1 Score across all 9 blog documents.
  3. Disagreement Analysis: Displays passages where model predictions differed from ground-truth for error review and prompt tuning.

[SECTION 12: EXPORT & ACADEMIC REPORTS]
- Purpose: One-click export hub for academic output formats.
- Key Exports:
  1. Excel Master Codebook (.xlsx): Multi-tab workbook containing Summary, Construct Distribution, Codebook, and Coded Segments.
  2. NVivo XML (.xml): QSR NVivo compatible hierarchy for seamless import into desktop CAQDAS software.
  3. Phase 3 Survey Items (.csv): Quantified 7-point Likert scale questionnaire items mapped from qualitative constructs.
  4. Thematic Analysis Report (.md): Full academic research report following Braun & Clarke's 6th stage.


--------------------------------------------------------------------------------
3. ARCHITECTURE, DATABASE & DEPLOYMENT
--------------------------------------------------------------------------------
- Backend: FastAPI Python Web Server (`src/dashboard/app.py`)
- NLP Engine: Hybrid TF-IDF vector similarity + Rule-augmented pattern matching (`src/nlp_thematic/coder.py`)
- Database: SQLite database (`outputs/research.db`), automatically seeded on boot with the 90-document dataset.
- Serverless / Vercel Support: Includes `vercel.json`, `api/index.py` entry point, `.vercelignore`, and fallback 
  to `/tmp/research.db` for read-only serverless execution on Vercel.
- Theme Aesthetics: High-contrast Black & White light theme, sharp 0px edges (`border-radius: 0px !important`), 
  and monochrome line stroke SVG icons.
